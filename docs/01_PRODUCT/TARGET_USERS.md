# Purpose

This document defines the target audience for BLACKOUT.

Understanding who the product is built for allows every design, engineering, and product decision to be evaluated against real user needs instead of assumptions.

BLACKOUT is intentionally focused.

It is **not** designed to solve every problem for every Android user.

---

# User Categories

BLACKOUT users are divided into three categories.

```
Primary Users
        │
        ▼
Secondary Users
        │
        ▼
Out of Scope Users
```

The product is optimized for Primary Users.

---

# Primary Users

These users directly influence product decisions.

Every major feature in Version 1 should improve their experience.

---

## 1. Media Listeners

### Description

Users who continue listening after visual interaction is no longer required.

Examples include:

- YouTube
- YouTube Music
- Spotify
- Podcasts
- Audiobooks

### Goals

- Hide the display.
- Reduce distractions.
- Save battery where possible.
- Continue listening without interruption.

### Frustrations

- Bright screens.
- Accidental touches.
- Locking the phone interrupts workflow.
- Existing apps feel cluttered.

---

## 2. Privacy-Conscious Users

### Description

Users who frequently use their phones in public environments.

Examples:

- Public transport
- Offices
- Libraries
- Cafés
- Classrooms

### Goals

- Prevent nearby people from viewing the display.
- Reduce unnecessary attention.
- Hide sensitive content quickly.

### Frustrations

- Locking the phone interrupts the current task.
- Bright displays attract attention.

---

## 3. OLED Enthusiasts

### Description

Users who prefer dark interfaces and own OLED or AMOLED devices.

### Goals

- Reduce screen brightness.
- Improve comfort in dark environments.
- Reduce power consumption where applicable.

### Frustrations

- Bright white interfaces.
- Poor dark mode implementations.
- Low-quality black overlays.

---

## 4. Minimalists

### Description

Users who intentionally choose lightweight, focused applications.

### Goals

- Perform one task quickly.
- Avoid unnecessary settings.
- Avoid advertisements.
- Use software that stays out of the way.

### Frustrations

- Feature bloat.
- Complicated interfaces.
- Excessive permissions.

---

# Secondary Users

These users benefit from BLACKOUT but are not the primary design focus.

---

## Travelers

Use navigation or media while keeping the screen visually unobtrusive.

---

## Students

Listen to educational videos or recorded lectures while studying.

---

## Professionals

Attend long meetings or voice calls where visual interaction is limited.

---

## Developers

Appreciate lightweight utilities and polished Android experiences.

---

# Out of Scope Users

BLACKOUT is **not** designed for these use cases.

Understanding what the product is **not** helps maintain focus.

BLACKOUT is not intended to become:

- A media player.
- A launcher.
- A task manager.
- A battery optimizer.
- A screen recorder.
- A parental control application.
- An automation platform.
- A productivity suite.

Requests pushing BLACKOUT toward these categories should generally be rejected.

# User Needs

The following needs are common across all primary users.

| Need | Importance |
|------|------------|
| Fast activation | Critical |
| Reliable overlay | Critical |
| Simple interface | Critical |
| Privacy | High |
| Low battery usage | High |
| Minimal permissions | High |
| Accessibility | Medium |
| Customization | Low |

---

# User Expectations

Users expect BLACKOUT to:

- Launch quickly.
- Feel native.
- Never interrupt the current application.
- Require minimal setup.
- Work consistently.
- Respect privacy.

Anything that reduces trust should be treated as a high-priority issue.

---

# User Pain Points

Current solutions often suffer from:

- Too many settings.
- Poor design.
- Advertisements.
- Slow performance.
- Confusing interfaces.
- Outdated visuals.
- Inconsistent behavior.

BLACKOUT aims to solve these issues through simplicity rather than additional features.

---

# Design Implications

The identified users directly influence product decisions.

Examples:

| User Need | Product Decision |
|-----------|------------------|
| Fast activation | One-tap Start button |
| Privacy | Black AMOLED overlay |
| Simplicity | Three-screen navigation |
| Reliability | Foreground service |
| Low battery impact | Lightweight overlay |
| Minimal learning | Intuitive UI |

---

# User Priorities

When trade-offs are required, priorities should be:

1. Reliability
2. Simplicity
3. Speed
4. Privacy
5. Battery Efficiency
6. Customization

This order should guide future development.

---

# Success Indicators

BLACKOUT succeeds when users:

- Activate it without hesitation.
- Understand it without instructions.
- Trust it to work consistently.
- Continue using it daily.
- Recommend it because it feels polished.
